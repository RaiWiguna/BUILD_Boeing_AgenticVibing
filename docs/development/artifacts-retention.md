# Artifact lifecycle dan retention Paket A

A09.1 menyediakan transport/storage, bukan report renderer. JSON/CSV/HTML bytes dihasilkan B melalui frozen `ArtifactSubmission` dan hasil job EXPORT. A memeriksa profile/transform version, UTF8/container, ukuran 1–16 MiB, hash, actual active attempt, scope, export grant creator, serta source rights immutable dan current. Rendering, redaction, CSV formula escaping dan HTML escaping tetap B.

Upload `/internal/artifacts/{id}?scope_id=...` hanya menerima worker credential dan metadata frozen di header. Bytes disimpan privat; submit port hanya mendaftarkan reference pending. `Jobs.result` mempromosikan artifact bersama accepted result dalam satu SQLite transaction. Partial upload, hash mismatch atau promotion rollback tidak menghasilkan artifact publik. Profile report `report-json-1`, `report-csv-1`, `report-html-1` memberi TTL maksimum 24 jam, dibatasi source expiry dan declared UTC expiry yang lebih pendek. TTL ini pilihan engineering lokal; bukan perubahan source policy atau klaim default produk final.

Browser mengakses `/api/v1/sessions/{sid}/artifacts`, `/{id}`, dan `/{id}/download` dengan optional `run_id`. Context/revision/grants berasal dari server. Download memverifikasi private package/hash, memerlukan capability dan seluruh source export rights, mencatat audit, dan memeriksa ulang authority/expiry setiap 64 KiB. Download selalu attachment dengan UUID filename, nosniff, no-store dan CSP sandbox. HTML tidak dirender sebagai halaman aplikasi. Expired artifact hilang dari inventory dan bytes dihapus pada recovery/expiry sweep; accepted metadata tetap inert. Revocation selama streaming menghentikan stream, tanpa menjanjikan response error baru setelah headers terkirim.

Retention host diaktifkan dengan `FLOWLENS_RETENTION_JOURNAL_PATH` atau `HostSettings.retention_journal_path`, bersama DB/import/raw storage. Journal wajib terpisah dari semua roots yang akan direstore; symlink/private-owner checks tetap berlaku. Tanpa konfigurasi journal, admin retention routes mengembalikan 503; host belum production-ready. Journal current harus dipertahankan operator, bukan diganti salinan backup lama.

Admin preview `/api/v1/admin/sessions/{sid}/purge-preview` menghasilkan scoped counts, opaque package/draft IDs, content digest dan inventory hash. POST `/purge` memakai JSON ketat maksimal 4 KiB: `key`, `reason` (`USER_REQUEST`/`RETENTION_EXPIRED`), `expected_inventory_hash`. CSRF/origin/admin berlaku. Perubahan contents walau jumlah rows sama menghasilkan VERSION_CONFLICT sebelum marker. `/purge-resume` melanjutkan plan yang terputus; `/audit?limit=...&after=...` hanya memberi metadata paginated, maksimum 100.

Coordinator menyimpan PREPARED plan, menutup akses session, mencabut worker scopes dan membatalkan penjadwalan jobs, lalu fsync external minimal tombstone sebelum menghapus raw/derived/import-staging bytes dan scoped source/domain/replay/job/grant/evidence rows. Trigger append-only ditangguhkan hanya pada maintenance UOW dan dipasang kembali transactionally; foreign keys diperiksa sebelum DONE/audit minimal. Ordinary mutations tetap append-only. Callback domain tidak memiliki commit/rollback/nested-maintenance/deferred-write authority. Digest scope luar memastikan perubahan global/session lain rollback sebelum erasure.

Registered fake B memakai `ModuleRegistration.inventory_namespaces` (`analysis`/subnamespace) dan `purge_handler(ctx,uow)` dengan frozen context/UOW signature. Inventory source events/tracks dan registered analysis records dibatasi session. Namespace tidak dikenal dan SQL tables di luar supported platform schema gagal NOT_EVALUABLE sebelum purge; generic custom B SQL inventory adapter belum diimplementasikan. Tidak ada B renderer/analysis/provider nyata dalam unit ini.

Startup menjalankan reconciliation sebelum ImportCommit memverifikasi packages dan sebelum menerima requests. Marker current mengalahkan database lama, PREPARED diteruskan, source yang habis retention dihapus, dan artifact expired disapu. Tombstone tetap memblokir context lama/fresh context. Journal chained/head/fsync mendeteksi truncation/corruption; ini bukan proteksi terhadap owner yang mengganti seluruh journal/head dengan versi lama. SQLite secure_delete diaktifkan, tetapi unit ini tidak mengklaim forensic deletion SSD, snapshots, backup/off-host copies, atau provider processing logs. Schedule removal backup dan consistent backup/restore CLI merupakan A09.3; deployment/operator eksternal tetap tahap delivery.

Evidence: [A09.1](../testing/a091-evidence.md). Synthetic fixtures dan fake callbacks hanya membuktikan platform lokal, bukan domain/provider/operational validation.
